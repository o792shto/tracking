# 競馬トラッキング馬券ゲーム 仕様書とClaude Codeプロンプト

Oct 9, 2026 · @Ooen

## コンセプトとゲームループ

架空の馬が、中央競馬の主要4場（東京・中山・京都・阪神）を再現した番組で走り、仮想コインで馬券を買い、データ放送風のトラッキング画面でレースを観戦するブラウザゲーム。目標は「中継のデータ画面を見ているような臨場感」と「展開を読む面白さ」の両立。

1. 今週のトップ：今週のレース一覧（同じ週の開催日をまとめて1つの画面に。各競馬場の10R・11R・12R。11Rがその日の重賞）
2. 出馬表：各馬の能力ヒント・脚質・近走成績・オッズを見る
3. 馬券購入：券種と馬番を選び、仮想コインで購入
4. 発走〜観戦：トラッキング画面でリアルタイム表示（倍速切替あり）
5. 確定・払い戻し：着順・タイム・配当表示、コイン加算
6. 次のレースへ（成績と所持コインは保存）。今週のレースが終わったら次の週へ

**前提**

- 競馬場名・重賞名は実在のもの（東京・中山・京都・阪神、2026年の重賞）を使う。馬名・騎手名は架空。主催団体のロゴやUIデザインは使わない
- 課金や換金要素はなく、仮想コインのみ
- 軍資金は1週間ごとに10,000コインが入金される（再入金・救済ボーナスは廃止）
- 今週のトップから次の週へスキップできる（買った馬券は結果どおり精算）

## 番組（中央競馬に寄せる）

- 1年 = 42週（重賞のある週だけ。7〜8月の夏は開催がない）。2026年のJRA主要4場の平地重賞98レース（`docs/reference/graded-races-2026.md`）を、その日のメインレース（11R）にする。目黒記念はダービーデーの12R（最終レース）。開催日（競馬場ごとの1日）は97日。土日と月曜の祝日をひとまとめにして1週とし、翌年は同じ日程を繰り返す
- 1日12Rの番組を作り、名簿の馬はすべてのレースを走る（成績が積み上がる）。ただしプレイヤーが観戦・購入できるのは各競馬場の10R・11R・12Rだけ。1R〜9Rは簡易な結果（見た目の強さ＋調子＋ばらつき）で決める。同じ週の開催日は1つの画面で1日として扱い、日付・レース番号・競馬場の順に行う
- 11R以外は典型的なクラス構成のテンプレート（未勝利・新馬・1勝・2勝・3勝クラス）で埋める。上半期は3歳戦と4歳以上、6月から2歳の新馬戦が始まり古馬は3歳以上。新馬戦は10月まで。クラスの数は名簿の馬の数に合わせた
- 重賞はすべて本来の格・レース名・距離・条件のまま行う（オープンへの置き換えはしない。クラシックを特別なものにするため。ユーザーの指示）
- 競馬場の回りは東京が左回り、中山・京都・阪神が右回り。コースの形は実際の競馬場に近い形（直線と円弧をつないだ周回、内回り・外回りの分岐、引き込み線、標高）で、ユーザー提供の推定モデル（`docs/reference/jra-tracks/`）を使う。1周・直線の長さ・高低差は公式値、コーナーの半径・分岐位置・引き込み線・標高の細部は推定。その場で実在しない距離（資料に発走地点がない距離。東京芝1200m・ダート1800m/2000m、中山芝2400m・ダート1600m/2000m、京都ダート1600m/2000m、阪神ダート1600m）は条件戦に出さない。条件戦の距離はその場で実在する標準距離から選ぶ。直線が長いほど差し・追込、短く小回りなほど逃げ・先行が有利になる
- 牝馬限定の条件戦は1日1レース
- オッズは小数第1位まで（0.1倍単位で切り捨て）。すべての券種で1.1〜99999.9倍。パリミュチュエル方式なので、実際のオッズは票の入り方で決まり、上限・下限に届くことはめったにない

## 馬の名簿（シーズンを通して出走する）

- 架空の馬の名簿（現役およそ1500頭）を持ち、毎週の番組に出走させる。出馬表の近走は実際の成績
- 毎年6月に2歳馬（480頭、牡牝半々）が名簿に入る。素質（能力の平均）は正規分布で、ひと握り（約1割）の素質馬は右にはみ出す
- 年齢で能力が変わる。2〜3歳は成長途中（3歳の秋にほぼ完成）、4〜5歳が完成、6歳から衰える。早熟・晩成の型がある
- クラスは勝ち数で上がる（未勝利→1勝→2勝→3勝→オープン。重賞・オープンで勝てばオープン）。降級はない
- 出走馬は週の初めに上のクラスのレースから決める（G1→G2→G3→3勝→2勝→1勝→新馬→未勝利）。1頭は1週に1レースまで。年齢・性別の条件を守り、距離・馬場が合うレースを選ぶ。重賞は総合力・賞金・適性の高い順
- 使い詰めにしない（ユーザーの指示）：前走からの間隔は未勝利・1勝クラス3週、2勝・3勝クラス4週、オープン5週以上。G1を走ったあとは6週（次もG1なら4週）。1年に走るのはG1馬6走・オープン馬7走・それ以外9走まで（条件戦で頭数が足りないときだけ、間隔を1週詰めて上限も超えてよい）
- 同世代の上位の馬は、6週以内に向いたG1があればそこを目標にする。G1の4週より前で、8週以上休んだあとの前哨戦1つだけに出る
- 1着の賞金（ユーザー指定）：G3 4000万円。G2は2歳戦4000万・3歳戦5500万・古馬戦7000万。G1はジャパンC・有馬記念5億、ダービー・天皇賞（春・秋）・宝塚記念・大阪杯3億、皐月賞・菊花賞2億、2歳戦8000万、牝馬限定1億5000万、それ以外（マイル・短距離）1億8000万。2着40%・3着25%・4着15%・5着10%。条件戦はオープン2400万・3勝1800万・2勝1500万・1勝1000万・新馬700万・未勝利550万
- 海外遠征：サウジカップ・ドバイ（ターフ・シーマクラシック・ワールドカップ）・クイーンエリザベス2世C・凱旋門賞・ブリーダーズカップ・クラシック・香港国際競走（ヴァーズ・スプリント・マイル・カップ）。日付は毎年のおおよその時期で、近い開催週に行う。日本のトップに近い馬がときどき挑戦し（1レース3頭まで）、結果は競馬ニュースと馬の戦績に残る。海外の馬は名簿にいないので、着順は日本馬の力と相手の強さ（レースごとの目安）から決める。賞金は実際のおおよその額
- 故障：1走ごとに約1.2%。6〜24週の休養、そのうち15%は引退
- 引退：3歳の未勝利馬は夏明け（9月の最初の週）、7歳は年末。G1馬は年末に一定の確率で種牡馬・繁殖入り。4歳以上の条件馬で直近5走に3着以内がなければ年末に一定の確率で引退。重賞を勝っていない引退馬は名簿から外す
- 夏は開催がないので、夏明けの週に「競馬ニュース」で夏に力をつけた上がり馬を3〜5頭発表する（3〜4歳の条件馬。能力が3〜6点上がる）
- 年末に年度表彰（年度代表馬・最優秀2歳/3歳/4歳以上の牡馬・牝馬・短距離馬・ダートホース）
- ゲーム開始の6年前から簡易な結果で世界を動かしておき、各世代の馬と成績をそろえる（2025年の重賞の結果と表彰が残る）
- 名簿は圧縮してゲームの進み具合とは別に保存する。データを消すと新しい世界で最初から

**画面**

- 今週：今週のレース一覧と競馬ニュース。「結果だけ見る」は結果画面へ行かずに一覧のまま次のレースへ進む（ユーザーの指示）。確定したレースには収支と「詳細」ボタン（着順・払い戻し）
- 設定：軽量モード・効果音・実況の字幕・ライトモード・すべてのデータを消して最初から
- データ：カレンダー（1年の開催と重賞の勝ち馬）、ランキング（今年の賞金・通算賞金・G1勝利数、年齢別）、重賞勝ち馬（年別・G1のみ）、年度表彰、ニュース
- 馬の詳細：性齢・脚質・クラス・通算成績・獲得賞金・主な勝ち鞍・表彰・近走（出馬表やデータ画面の馬名から開く）

## 技術構成とアーキテクチャ

シミュレーションと描画を完全に分離するのが最重要の設計判断。シミュレーションは描画なしでも動き、テストで何千レースも回して勝率の偏りを検証できるようにする。

| 項目 | 採用案 | 理由 |
| --- | --- | --- |
| 言語・ビルド | TypeScript + Vite | 型でシミュレーションのバグを減らせる |
| UI | React | 出馬表・馬券画面など状態の多い画面向き |
| トラッキング描画 | Canvas 2D（重ければ PixiJS に移行） | 18頭程度なら Canvas 2D で60fps可能 |
| 状態管理 | Zustand | 軽量でゲーム状態と相性がよい |
| アニメーション | Framer Motion（UI部分のみ） | 順位表の並び替えなど |
| テスト | Vitest | シミュレーションの統計テスト |
| 保存 | localStorage（try/catchで保護） | サーバー不要 |

**モジュール構成**

- `sim/`：コース定義、馬データ生成、レースエンジン（固定タイムステップ、シード付き乱数で再現可能）
- `betting/`：オッズ計算、馬券判定、払い戻し
- `render/`：トラッキングCanvas、カメラ、エフェクト
- `ui/`：出馬表、馬券購入、順位表、ラップ表示、結果画面
- `store/`：所持コイン、開催データ、成績

**データの流れ**：エンジンが毎ステップ各馬の「距離・横位置・速度・スタミナ」を出力 → 描画側はそれを補間して表示するだけ。描画側からシミュレーションの結果を変えない。

## レースシミュレーション仕様

見応えの土台はここ。脚質と展開で結果が変わり、毎回違うドラマが生まれることを目指す。数値は初期値で、テストしながら調整する前提。

**コース**

- コースを距離計測ライン（直線＋円弧の列）で定義し、各馬は「スタートからの距離」と「内ラチからの横位置」で表す
- 距離は芝が1200m / 1600m / 2000m / 2400m、ダートが1200m / 1600m / 1800m / 2000m（1800mは中山・京都のダートが1200mだけにならないよう追加）。右回り・左回りを用意
- 馬場状態（良・稍重・重・不良）でタイムとスタミナ消費が変わる。芝は道悪で時計がかかり、ダートは道悪で砂が締まって速くなる

**馬の能力**

- スピード、スタミナ、瞬発力（末脚）、パワー、気性、スタート巧拙
- 脚質：逃げ・先行・差し・追込
- 距離適性・馬場適性、当日の調子（ランダム）
- 出馬表には能力値を直接出さず、近走成績や短評からプレイヤーが推測する

**レースの進行**（固定タイムステップ、例：1/60秒）

1. スタート：スタート巧拙＋乱数で出遅れ判定
2. 序盤：脚質ごとの目標位置取りへ向かう。逃げ馬同士は競り合うとスタミナを余分に消費
3. 中盤：隊列が落ち着き、全体のペースが決まる（ハイペースなら前が苦しくなる）
4. 仕掛け：脚質と騎手判断（乱数）で残り800〜400mから加速開始
5. 直線：残りスタミナと瞬発力で最高速が決まり、スタミナ切れの馬は失速
6. ゴール：ゴール線通過時刻を補間で精密に求め、着差を算出

**位置取りと不利**

- 前の馬との距離が近いと減速（前が壁）。外に持ち出すと距離ロスが増える
- カーブで外を回るほど走行距離が伸びる
- 低確率のイベント：出遅れ、掛かり（序盤にスタミナ浪費）、進路が開かない

**検証の基準**（テストで確認）

- 1番人気の勝率がおおむね30%前後、人気薄の激走もときどき起きる
- 脚質ごとの勝率が極端に偏らない
- 走破タイム・平均ラップ・上がり3F・ラップ形状が、JRAのラップタイム参考値（`docs/reference/jra-lap-reference.md`）の目安から大きく外れない。参考値のない条件は推測で埋めず「参考値なし」として極端な値だけを見る
- 同じシードなら同じ結果になる

## トラッキング画面と演出仕様

デザインの方向性は「暗い背景に発光するデータ表示」。放送局のデータ画面のような精密さを、オリジナルの配色とレイアウトで作る。

**コース俯瞰図**

- 暗い緑〜紺の背景に、コース形状・内ラチ・ハロン棒（200mごと）・ゴール線を線画で描く
- 馬は枠色の円＋馬番。自分の買った馬は外側にリングを付けて強調
- 各馬の後ろに速度に応じた長さの軌跡（残像）を描く
- 位置は60fpsで補間し、カクつかせない

**カメラ**

- カメラは「全体／先頭／選択馬」の3つ（自動切替は忙しいのでユーザーの指示で廃止）。最初は先頭追従
- 選択馬：順位表でタップした馬のまわりに大きく寄る
- 接戦のゴール前はスロー再生（0.5倍程度）

**データオーバーレイ**

- 順位表：順位・馬番・馬名・先頭との差（馬身）・現在速度。順位変動時は行がスライドし、上昇は緑、下降は赤で一瞬光る
- ラップ表示：200mごとのラップが積み上がる棒グラフ＋前半・後半のペース判定（ハイ／平均／スロー）
- 馬群の長さ：先頭から最後方までの距離を表示
- 残り距離カウンターと経過タイム
- 自分の馬券の状況：「現在の着順なら的中／不的中」を常時表示

**演出イベント**

- ゲートオープン：カウントダウン→一斉スタート、出遅れた馬にマーカー
- 残り600m・400m・200m通過でテロップ
- 接戦時（1・2着の差が小さい）：ゴール前スロー、写真判定の演出（数秒待ってから確定）
- 確定後：結果表（着順・タイム・着差・上がり3F）、払い戻しのカウントアップ、高配当時の特別演出
- 効果音・実況風テキスト（任意、オン／オフ切替）
- 着差：大きく抜け出した先頭馬は、残り300mから騎手が追うのをやめて流す（流し始める差は馬ごとに1.5〜4.5馬身）。5馬身以上の勝ちは全体の1〜2％
- 実況：1000m通過はタイムだけ。隊列は集団ごとに前から順に、人気馬（1・2番人気）の位置、重賞は「〇〇、△△を制しました」。読み上げはなし（ユーザーの指示で削除）
- 実況は名簿の馬の成績を使う。クラシック（牡馬：皐月賞・日本ダービー・菊花賞、牝馬：桜花賞・オークス・秋華賞）は「クラシックの一冠目を制しました！」「二冠達成！」「三冠達成！」、二冠・三冠がかかる馬は序盤に紹介。ほかに G1初制覇・G1何勝目、重賞の連覇、3連勝以上、前走大敗からの巻き返し、重賞連勝、デビュー勝ち・初勝利
- 実装メモ（段階6）：スローは1・2着の差が1/2馬身以内（約2割のレース）で、1着のゴール1.6秒前から2着のゴール0.5秒後まで0.5倍。写真判定は同着・ハナ・アタマ（約5％）で、判定中は順位表の上位と馬券の的中を伏せる。高配当は1枚の払い戻しが賭け金の50倍以上、または合計5万コイン以上。効果音は Web Audio で合成し、設定でオン（デフォルトはオフ）
- レース中の出来事（出遅れ・掛かり・進路をなくした）は、その馬に数秒だけ札を出す

**操作**：倍速（1x / 2x / 4x）、スキップ、リプレイ（同じシードで再生）

## 馬券・オッズ・払い戻し仕様

オッズはパリミュチュエル方式（投票総額から控除率を引いて的中票で分ける）で計算し、本物らしい配当の分布を出す。

| 券種 | 的中条件 | 実装段階 |
| --- | --- | --- |
| 単勝 | 1着を当てる | 最初 |
| 複勝 | 3着以内（7頭以下は2着以内） | 最初 |
| 馬連 | 1・2着の組み合わせ（順不同） | 最初 |
| ワイド | 3着以内の2頭（順不同） | 段階7で実装 |
| 馬単 | 1・2着を着順通り | 段階7で実装 |
| 3連複 | 1〜3着の組み合わせ（順不同） | 段階7で実装 |
| 3連単 | 1〜3着を着順通り | 段階7で実装 |

**オッズの作り方**

- 各馬の「真の強さ」から勝率を推定し、そこに大衆の偏り（人気馬・前走好走馬に票が寄る）とノイズを加えて仮想投票を生成
- 控除率はJRAに合わせる（単複20%、馬連・ワイド22.5%、馬単・3連複25%、3連単27.5%）。複勝・ワイドは配当の幅（最低〜最高）で表示
- 組み合わせの確率はハービルの公式で各馬の勝率から出す。オッズはすべての券種で1.1〜99999.9倍
- 見た目の強さ（勝率の土台）は、シミュレーションの着順（1〜3着）に条件付きロジットを当てはめて決めた重みで計算する（巡航速度・末脚・スタミナの余裕・脚質・枠）。名簿の馬の観戦レースで、見た目の強さが一番の馬の勝率はおよそ30%（実際の1番人気は約32%）
- 発走前に数回オッズが変動する演出
- 人気と実力のずれが「予想する意味」になるので、ここは調整しがいがある

**購入UI**

- 券種選択 → 買い方（通常・ボックス・流し・フォーメーション）→ 馬番選択 → 1点あたりの金額
- 流しの軸は2頭の券種で1頭、3頭の券種で1〜2頭。馬単・3連単の流しは軸が上の着順（1着、2頭なら1・2着）。マルチはなし
- まとめ買いは1点ずつの馬券に展開して買い、一覧・観戦・結果・成績ではまとめて表示する
- 購入前に点数・合計金額・想定配当を表示
- 1レースの購入上限はなし（所持コインの範囲で買える。ユーザーの指示で廃止）

**保存データ**：所持コイン、購入履歴、回収率、最高配当、今週の進み具合。名簿の世界は別に保存

## PC/スマホのレイアウト

同じ情報を、PCは「一画面に全部」、スマホは「コース図優先＋切り替え」で見せる。ブレークポイントは幅768px。

| 要素 | PC（横長） | スマホ（縦長） |
| --- | --- | --- |
| コース俯瞰図 | 画面左〜中央の大部分 | 画面上部（横幅いっぱい、高さ約45%） |
| 順位表 | 右サイドに常時表示（全頭） | 図の下に上位5頭＋自分の馬、タップで全頭 |
| ラップ・ペース | 下部に横長で常時表示 | タブ切替（順位／ラップ／馬券） |
| 馬券の的中状況 | 右上に常時表示 | 画面最下部に固定の細いバー |
| 操作ボタン | 下部ツールバー | 親指で押せる下部に大きめに配置 |

**共通ルール**

- Canvasは devicePixelRatio に合わせて解像度を上げ、スマホでもにじませない
- スマホ横向きにしたらPCに近いレイアウトへ切り替え
- タップ領域は最低44px、文字は最小12px
- 低スペック端末向けに軌跡・エフェクトを減らす「軽量モード」
- 実装メモ（段階5）：観戦画面は幅768px未満の縦長で「スマホ縦」、高さ560px未満の横長で「スマホ横」（コース図＋右にタブ、ラップもタブへ）、それ以外はPC。軽量モードは軌跡・発光・グリッドなし、解像度1倍、30fps。設定（軽量モード・効果音）はヘッダーの「設定」から変え、ゲームの保存とは別に保存する

## 進め方のコツと注意点

一番効くのは「段階1のシミュレーションを納得いくまで調整してから描画に進む」こと。展開が単調だと、演出をいくら磨いても見応えは出ない。

- 1回のプロンプトで全部作らせない。段階ごとに動かして確認し、気になる点を具体的に伝えて直させる
- 「もっとかっこよく」より「順位が入れ替わった瞬間が分かりにくい」「直線の加速感が弱い」のように、場面と問題で伝える
- 気に入った見た目になったら、配色・フォント・余白のルールを CLAUDE.md に追記させてブレを防ぐ
- 各段階の終わりに git commit しておくと、失敗した変更を戻せる
- 数値（勝率・ペース・控除率など）はこの仕様の初期値。本物の競馬の統計に合わせ込みたい場合は、別途データを調べて基準を決める必要がある（ここでは検証していない）
